00Teacher brief

Start here. You can teach the course from this section without guessing what the pack is for.

Mission

Hamid wants to understand, end to end, a real O2C Unbilled KPI on Databricks Free. The path is ODS → bronze → silver population → consumption semantic layer (Metric View) → gold published values → Genie ad hoc. Same compile path the whole way. Meaning (ontology) stays off the formula.

He should be able to say what each seat does, what it is not, and why two honest “customer” reports fight. He should not mix this pack with Track A.

02Honest formula seats

Three places people over-claim. Keep them separate when you talk.

SeatWhat actually lives hereWhat does not
fct_unbilled Ticket gate (delivered, no posted invoice as of 2026-08-01, quality-hold out) and unbilled_usd = gallons_net * contract_price. One row per BOL. 12 tickets. $179,934.00. Published gold. A certified formula object. A customer grain choice.
Metric View YAML SUM(source.unbilled_usd) and COUNT(1). Fields you may group by. The compiler writes the SELECT / GROUP BY. The unbilled rule. Ontology IRIs (version 0.1 does not embed them). A second copy of gallons_net * contract_price.
Gold / Genie / SQL Act 2 Gold: MEASURE() on each certified view (published measure only). Genie: MEASURE() on the matching certified view. SQL Act 2: MEASURE(unbilled_usd) on Unbilled. RC-1 per KPI. A second SUM(fct_unbilled). Gold Unbilled-only after a full run. Export-to-metric-view. SELECT *.

Delete the Metric View and Act 1 against the fact still works. That is the production pattern: population first, compiler second. The walkthrough says so on purpose.

03Lakebase ODS

dataexpert-day1 / databricks_postgres / o2c_unbilled only. Ops tables. Not the compiler.

What it is

The operational landing for the seven seeds. It is a new schema on the existing Lakebase project dataexpert-day1, database databricks_postgres. Schema name is locked: o2c_unbilled.

What it holds

Seven Postgres tables loaded from data/*.csv. Expected counts: parties 8, party_roles 10, products 3, terminals 3, tickets 19, invoices 6, invoice_lines 6.

What it does at runtime

CREATE SCHEMA IF NOT EXISTS o2c_unbilled. Then create-if-not-exists, truncate or delete those seven tables, insert the CSVs. Scripts refuse any other schema or database. They never DROP SCHEMA. They never write into other day1 schemas.

What it is not

Not a second Lakebase project. Not Azure. Not the consumption semantic layer. Not gold. Not a place that authors Unbilled USD. Invoices live here as ops facts. The unbilled gate is applied later, on Databricks.

Where it lives

scripts/00_lakebase_ods.py, sql/00_lakebase_ods.sql, sql/00_README.md, seeds in data/. Host, user, and password stay in local .env. Never in the repo. Never in this file.

How it connects

In: the seven CSVs. Out: the uv pipe reads these tables and writes Databricks raw_*. Nothing in the warehouse queries Lakebase directly.

Failure if you skip it

You lose the “ops system of record” seat. That is allowed. scripts/02_load.py (or the SQL-editor VALUES path in sql/99_full_load.generated.sql) can land CSVs straight into raw_*. Then Act 0 never ran. Bronze still has to exist. Do not invent a federated join to “skip the skip.”

Locked project and schema

Tempted to create a new Lakebase project? Don’t. Act 0 is a schema on dataexpert-day1. Scripts exit if LAKEBASE_SCHEMA is anything other than o2c_unbilled.

04uv Python pipe

databricks-sdk + SQL connector + psycopg. Python copies rows. No federated join.

What it is

The Mac-side runner for Track B. A uv venv talks to Lakebase with psycopg and to the Free warehouse with the Databricks SQL connector. Python is the pipe. The warehouse never joins out to Postgres.

What it holds

No durable data of its own. It holds connection helpers, placeholder substitution, and the script order. Tokens and passwords are read from local .env and refused if empty. They are not printed.

What it does at runtime

00b_land_replica.py SELECTs each Lakebase ops table, then CREATE OR REPLACE TABLE … AS SELECT * FROM VALUES … into raw_*. Later scripts run facts, the version 0.1 Metric View, queries, store, KPI 2 and 3, then Genie (one agent, three views - after those views exist). Each script prints the SQL it sends.

What it is not

Not MetricFlow. Not dbt. Not DuckDB. Not a federated Lakebase query from DBSQL. Not Azure CLI. Not a second formula. 02_load.py is a shortcut that skips Lakebase. Use it only when Act 0 is off.

Where it lives

pyproject.toml, scripts/config.py, scripts/00_lakebase_ods.py, scripts/00b_land_replica.py, then 01 through 09. Run from demos/o2c-unbilled-databricks-free/ with uv run python scripts/….

How it connects

In: Lakebase o2c_unbilled (or local CSVs on the shortcut). Out: Unity Catalog tables and the Metric View on the Free warehouse. Genie is created or found by title through the same SDK.

Failure if you skip it

You can still run the SQL-editor path (sql/99_full_load.generated.sql then sql/05_store.sql). You then have no Lakebase replica story. Do not replace the pipe with a warehouse query against Lakebase. That join is out of scope.

05Bronze raw_* replica

Same seven seeds, now in Unity Catalog. Replica, not a certified number.

What it is

Warehouse copies of the ops tables: raw_parties, raw_party_roles, raw_products, raw_terminals, raw_tickets, raw_invoices, raw_invoice_lines. Default home is workspace.o2c_unbilled (or your catalog / default if schema create is denied).

What it holds

The same 8 / 10 / 3 / 3 / 19 / 6 / 6 rows. All 19 BOL tickets, including quality-hold and already-billed lifts. All six invoices, including the post-as-of posted invoice and the draft.

What it does at runtime

Sits still. sql/02_facts.sql joins these tables to build dims and fct_unbilled. Act 1 can also be taught against the fact, not against bronze. Bronze is the raw evidence.

What it is not

Not the population. Not gold. Not the consumption semantic layer. Not a place Genie should query as the measure source. Do not point Genie at raw_*.

Where it lives

Created by scripts/00b_land_replica.py, or scripts/02_load.py, or sql/01_land.sql Part B, or the VALUES head of sql/99_full_load.generated.sql. Seeds stay in data/.

In: Lakebase via the pipe, or CSVs. Out: silver dims and fct_unbilled. Invoice header + lines are why a ticket is or is not unbilled later.

Failure if you skip it

06Silver dims + br_party_role

Thin star-ish objects. They teach party vs site. The Metric View does not join them.

What it is

Four silver tables built in sql/02_facts.sql: dim_party, dim_site, dim_product, br_party_role. dim_kpi_metadata is also silver, but it is a different seat (section 08). Keep them mentally apart.

What it holds

Parties (legal / operating names). A role bridge: payer / sold_to / bill_to. GCA holds all three. Sites are terminals (HSC, DAL, BMT), not customers. Products carry contract price and list price. Contract ≠ list. That matters for the sloppy twin, not for the certified path.

What it does at runtime

Gives names and roles you can read. dim_site is joined when building fct_unbilled so site_name is already on the fact. After that, the Metric View reads one table. No YAML joins.

What it is not

Not the population. Not gold. Not the formula. Not a customer dimension that picks payer vs sold-to for you. Site is a location. Do not file it under “customer.”

Where it lives

sql/02_facts.sql (and the facts block inside 99). Driven by scripts/03_facts.py on the uv path.

How it connects

In: raw_parties, raw_party_roles, raw_terminals, raw_products. Out: names denormalized onto fct_unbilled. The role bridge is the teaching object for “GCA is payer and sold-to.”

Failure if you skip it

You can still denormalize names from raw_* onto the fact. You lose the explicit party / site / role objects. The grain lesson gets harder to point at. Do not skip the idea, even if you skip the extra tables.

07fct_unbilled

Population / compiler source. Not gold. Not a layer named Certified. Not the published formula.

What it is

The sealed population at ticket grain. One row per unbilled BOL as of 2026-08-01. This is the table the Metric View reads. Easy to audit. Delete the Metric View and you can still query this table. That is on purpose.

What it holds

12 tickets. Grand total $179,934.00. Each row already has unbilled_usd = gallons_net * contract_price, plus payer / sold-to / site names, product, delivery date, and as_of_date.

What it does at runtime

Applies the ticket gate: status = delivered, no posted invoice line with invoice_date <= 2026-08-01, quality-hold excluded. Then multiplies net gallons by contract price. Names are denormalized so the Metric View stays one source table.

What it is not

Not gold published KPI values. Not a layer called Certified. Not a customer grain choice. Not something Genie should query as the measure source. Not a second SUM waiting to be copied into gold.

Where it lives

sql/02_facts.sql. scripts/03_facts.py runs it. The facts block in 99 is the same rule. Comment at the top of 02 says it plainly: compiler source, not gold.

How it connects

In: raw_tickets + products + parties + dim_site + posted invoices as of. Out: Metric View source. Act 1 groups this table twice (sold-to vs payer) to show the fight.

Failure if you skip it

There is no population. The Metric View has no source. Gold and Genie have nothing honest to compile. Do not “fix” that by summing bronze in gold. Rebuild the fact.

Honest seat: the gate and the multiply live here

This is where a ticket becomes unbilled dollars. The Metric View does not repeat gallons_net * contract_price. It sums the column this table already made. Gold and Genie must not re-encode the gate either.

08dim_kpi_metadata

One row per KPI (all certified). A pointer. It does not author the formula and it does not restate the gate.

What it is

The Store catalog. Silver. One row per KPI, all certified. After a full run: three rows. Owner, status, unit, allowed grains, and two pointer columns. Meaning IRI on the side.

What it holds

Three certified rows after 06→08→09 (or 08/09 then 06 - replace-by-kpi_id keeps the others). Pointer is the measure name, object is the view. Unbilled: KPI-O2C-UNBILLED-USD / unbilled_usd / unbilled_usd view / #UnbilledState. Contract-vs-list: KPI-O2C-CONTRACT-VS-LIST-USD / delivered_contract_usd / contract_vs_list_usd view / #Obligation. Temp-adjusted: KPI-O2C-TEMP-ADJUSTED-USD / temp_adjusted_usd / temp_adjusted_delivered_usd view / #Obligation. No #DeliveredTicket.

What it does at runtime

Answers “what is this KPI, who owns it, where is the compile object?” Gold joins it on kpi_id. It does not compute a dollar. It does not run MEASURE(). After 05/06 the Unbilled row is present; after a full run expect 3 certified rows.

Where it lives

09Metric View unbilled_usd

YAML version 0.1 inside CREATE VIEW WITH METRICS. Fields + measures. This pack’s consumption semantic layer.

What it is

A Unity Catalog Metric View named unbilled_usd. YAML lives inside CREATE OR REPLACE VIEW … WITH METRICS LANGUAGE YAML AS $$ … $$. One statement. Do not split the block. Version 0.1 is the pack dialect: source, fields, measures.

What it holds

Source: fct_unbilled (no joins). Fields: payer, sold_to, site, site_name, as_of, delivery_date, product. Measures: unbilled_usd = SUM(source.unbilled_usd), unbilled_ticket_count = COUNT(1).

What it does at runtime

The compiler writes the SELECT / GROUP BY. You ask with MEASURE(). You choose the group-by. The ticket set does not change. Swap sold_to for payer or site. Same $179,934.00. Different rows.

What it is not

Not ontology. Not gold. Not the ticket gate. Not a second multiply. Not MetricFlow (ticket__sold_to prefixes do not exist here). Not a time spine. Version 0.1 is fields and measures only. Do not add extra YAML keys.

Where it lives

scripts/04_metric_view.py (the live-proven 0.1 statement). sql/03_metric_view.sql is being rewritten to that same 0.1. The 0.1 block in sql/99_full_load.generated.sql is the warehouse-UI twin. Official create / query docs: Databricks Metric Views, 2026.

How it connects

In: fct_unbilled only. Out: gold FROM MEASURE(), SQL Editor Act 2, Genie ad hoc. Metadata points at the measure name and the view. Turtle agrees in English. Turtle is not an input.

Failure if you skip it

You still have a population. You do not have a consumption semantic layer. Gold must not fall back to SUM(fct_unbilled). Genie must not invent a view. Act 1 can still teach the grain fight against the fact. Acts 2 and 3 cannot run.

One compile dialect: version 0.1

Fields + measures. That is what compiled on Free on 2026-08-14. SELECT * was refused with METRIC_VIEW_MISSING_MEASURE_FUNCTION. Do not send learners toward an unproven richer YAML. Monaco auto-indent can mangle the block. Paste as one statement.

version: 0.1
source: {{catalog}}.{{schema}}.fct_unbilled
fields:
  - name: payer
    expr: source.payer_name
  - name: sold_to
    expr: source.sold_to_name
  - name: site
    expr: source.site_code
  # plus site_name, as_of, delivery_date, product
measures:
  - name: unbilled_usd
    expr: SUM(source.unbilled_usd)
  - name: unbilled_ticket_count
    expr: COUNT(1)

09bKPI 2 · contract_vs_list_usd

Second certified KPI. Not a second Unbilled. Joins + filter + multiply in YAML. Gold publishes it. Genie asks it with MEASURE() on the matching view.

What it is

A second Metric View: delivered-ticket value at contract vs list. Same compiler, different formula. Source is raw_tickets (bronze star), not fct_unbilled. No population fact. The multiply lives in YAML.

What it holds

Four star joins, aliases product_dim / sold / payer_dim / site_dim (not product / sold / payer / site - those collide with field names → INVALID_EXTRACT_BASE_FIELD_TYPE). Filter: delivered, temp ≥ 80, gallons ≥ 5000, July 2026, gasoline|distillate. Engine default is LEFT OUTER; the filter on product_dim.product_family is an implicit inner (every ticket has a product).

What it does at runtime

Version 0.1 first (joins + filter + measures). If Free refuses joins/filter on 0.1, retry the same shape as 1.1 on this view only. Do not change unbilled_usd. Consumers only MEASURE(). Published measure for Gold: delivered_contract_usd only (other MEASURE()s are query-only).

What it is not

Not Unbilled. Not a second Unbilled formula. Not a population fact. Not a second formula Genie authors - Genie attaches this view and asks MEASURE(delivered_contract_usd). Not #DeliveredTicket - catalog IRI is #Obligation.

Where it lives

sql/06_complex_metric.sql / scripts/08_complex_metric.py. Catalog row KPI-O2C-CONTRACT-VS-LIST-USD, pointer delivered_contract_usd, object contract_vs_list_usd, status certified.

How it connects

In: bronze star. Out: Gold grains enterprise / sold_to / product FROM MEASURE(delivered_contract_usd). Replace-by-kpi_id. Unsliced: contract $110,064.00 / list $114,450.00 / 7 tickets.

Failure if you skip it

Unbilled still compiles. You lose the joins/filter/multiply teaching point and the second certified catalog row. Do not flatten the formula into a new fact to “make gold easier.”

09cKPI 3 · temp_adjusted_delivered_usd

Not the ticket gate. Not the multiply. Not the consumption semantic layer by itself (the Metric View is). Not Azure classic compute. Not custom storage. Not a second warehouse you spin up “just for Genie.”

Where it lives

Your Free Edition workspace, signed in at login.databricks.com. Pattern *.cloud.databricks.com. If you see *.azuredatabricks.net, you are in the wrong product. Stop. Warehouse id and host stay in local .env, never here.

How it connects

In: every script and every SQL file. Out: every table and the view. It hosts the picture. It does not decide meaning.

Failure if you skip it

There is no Track B. DuckDB is Track A. Do not stand up Azure to “get a real warehouse” for this lesson. Official Free limits (2026): one 2XS serverless warehouse, restricted outbound internet, non-commercial.

16Quiz

Ten short questions. One idea each, in lesson order. Answers are collapsed. Ask Hamid to answer out loud before opening them.

Q1 · Unbilled is a state

Is Unbilled a KPI class, a customer class, or something else?

Answer
Something else: a state of an Obligation. A delivered BOL not yet invoiced. Quality-hold is never billed and never unbilled. Turtle names that. The Metric View does not.
Q2 · customer_grain

What is customer_grain in this pack, and who picks it?

Answer
customer_grain ∈ {payer, sold-to, site}. You choose the group-by. The formula stays still. Site is a terminal, not a party. There is no fourth generic “customer.”
Q3 · two customer reports

Report A and Report B both total $179,934.00. Why do they still fight?

Answer
Same 12 tickets, different group-by. A has 4 sold-to rows. B has 3 payer rows. Apex Fuels LLC ($115,960.80 / 8) equals Houston Rack + Dallas Dealer. Adding those three “customer” lines double-counts. Aviation matches because GCA is both roles.
Q4 · population vs gold

What is fct_unbilled, and what is gold_kpi_value?

Answer
fct_unbilled is the Unbilled population / compiler source at ticket grain (12 rows, gate + multiply). KPI 2/3 have no population fact. gold_kpi_value is published instances per certified KPI FROM that view’s MEASURE(). Unbilled gold is 11 rows at enterprise / payer / sold_to / site. Population is not gold. Do not name a Certified layer on the fact.
Q5 · what the Metric View compiles

What does version 0.1 YAML actually compile, and what does it leave on the fact?

Answer
It compiles SUM(source.unbilled_usd) and COUNT(1) plus the fields you may group by. The ticket gate and gallons_net * contract_price stay on fct_unbilled. Do not call the view the only formula source of truth. Do not teach a richer YAML dialect.
Q6 · MEASURE() vs SELECT *

Why must a consumer write MEASURE(unbilled_usd) instead of SELECT *?

Answer
Every measure on a Metric View uses MEASURE(). SELECT * is refused (expect METRIC_VIEW_MISSING_MEASURE_FUNCTION) so you cannot treat the view like a table and re-aggregate. That refusal is the lesson, not a bug.
Q7 · C-10

What does C-10 split, and what must dim_kpi_metadata not do?

Answer
Ontology = meaning. Store catalog + Metric View = certified formula path. They agree. They are not one object. Metadata is one row per KPI (all certified) - after a full run, three rows. It points (formula_pointer = measure name / formula_object = view). It must not restate the gate or the multiply. Unbilled IRI #UnbilledState; delivered KPIs #Obligation. No #DeliveredTicket. Turtle does not compile.
Q8 · Genie

What is Genie allowed to do, and what is forbidden?

Answer
Allowed: find-by-title O2C certified KPIs, attach the three Metric Views, ask grain questions, answer with MEASURE() on the matching view. One agent, three views. Forbidden: Export-to-metric-view, querying fct_unbilled or raw_* as the measure source, re-encoding the multiply, documenting a space id, a second agent. A matching dollar from the wrong object is still a fail.
Q9 · three certified KPIs

How many catalog rows after a full run, how does gold refresh, and which measure does each KPI publish?

Answer
Three certified rows in dim_kpi_metadata. Gold is one table: CREATE TABLE IF NOT EXISTS, then replace-by-kpi_id (DELETE that id, INSERT FROM MEASURE()). Never CREATE OR REPLACE the whole gold table. Published measures: unbilled_usd, delivered_contract_usd, temp_adjusted_usd. Join aliases on KPI 2/3 are product_dim / sold / payer_dim / site_dim.
Q10 · Word hunt keys

What does SF-APEX map to? What is CONS-4412? What does warehouse 1000123 map to?

Answer
SF-APEX = no-map (Salesforce account_id is a relationship, not a role). CONS-4412 = Loading-Authorized Party (TAS consignee). Warehouse 1000123 = no-map (overloaded warehouse key; the same digits are two SAP roles).
