Locks honoured — cite, do not invent
  • C-10: ontology = meaning. Store catalog + consumption semantic layer = certified formula + compute. Ontology does not author formulas.
  • C-11: never say “semantic layer” unqualified. Say consumption semantic layer or Metric View. Programme compiler seat in demos = Databricks Metric Views / Unity Catalog.
  • RC-1: one certified formula, one compile path per KPI. Programme path = MEASURE() on that KPI’s Metric View. No second formula.

01 The rule

The catalog can list a hundred. A Metric View, a Gold table, and a Genie agent cannot each hold a hundred. That is the whole note.

  1. One Store catalog (the register) can list all 100.
  2. Many Metric Views — a view holds a few measures only when they share population, Silver star, and grain family.
  3. Gold follows grain — when grains diverge, one published table (or mart) per KPI. Folding instances into one gold_kpi_value was the demo shortcut.
  4. Genie is a question set, not the enterprise. Several agents by domain / job, each with a small set of views.
Industry shape (grounding, not a lock)

Downstream O&G. Customer lane = order-to-cash. Ops / Tech lane = plan-to-produce. Those are different processes. They do not share a Metric View just because both sit in the same catalog.

02 Four seats — what each owns

C-10 splits meaning from formula + compute. These four seats sit on the formula + compute side. None of them is the ontology.

Store catalog The register. One row per KPI. Pointers: measure name, Metric View, calc_version. Can list all 100. Not the compile. Not meaning SoT.
Metric View The formula object. Compiles the certified expression. A few measures only when they pass the grouping test (§03). Path = MEASURE() (RC-1).
Gold Published instances FROM MEASURE(). Frozen snapshot — not a second formula, not formula SoT. Grain decides the table, not the catalog count.
Genie Ad hoc consumer, not an author. A question set over a small set of views. No Export-to-metric-view. Not the enterprise.

03 When KPIs may share a Metric View

A view may hold a few measures only when all three hold:

  1. Same population — the same “who counts.” Payer is not sold-to. A site is not a customer account.
  2. Same Silver star — the same fact + dimension family. Different Silver tables get their own view.
  3. Same grain family — the same atomic grain, or a grain that rolls up without rewriting the measure. Different grains get their own view.

Fail any one and the KPI gets its own Metric View. A different process — order-to-cash versus plan-to-produce — fails all three in practice. Do not fold them because the catalog already lists both.

Don’t collapse process into one view

Customer O2C and Ops / Tech plan-to-produce are not one consumption semantic layer file. They may share a catalog. They do not share a Metric View.

04 Gold when grains diverge

Gold is the published snapshot of the compile — instances FROM MEASURE(), versioned and immutable. It is not formula SoT (C-10 / RC-1). When two KPIs do not share a grain, do not stack their instances in one table and hope a kpi_id column sorts it out.

Practice already agreed: often one Gold table (or mart) per KPI when grains diverge. The demo folded three O2C KPIs into one gold_kpi_value. That was the shortcut. It taught the compile path. It is not the production shape.

Open — not locked

Gold physical shape at programme scale is open. One mart per KPI is the working note when grains diverge. The pack does not lock the physical form. Do not promote this paragraph into a lock.

05 Genie by consumption context

Genie is a question set over a small set of Metric Views. It is not the catalog, not the compiler, and not the enterprise. Several agents, split by domain or job — Customer O2C in one, Ops / Tech plan-to-produce in another — each seeing only the views that belong to that job.

One agent pointed at 100 KPIs repeats the failure we already saw: Apex guess, ILIKE on names, GROUP BY ALL that silently widens the grain. The model starts shopping across unrelated measures. Cross-domain numbers do not go into a mega-Genie. They go to the catalog (which KPI, which view, which Gold) or to a composed report that already joined the certified results.

Open — not locked

Exact Genie-agent count is open. The rule is “several, by consumption context,” not a headcount. Do not invent an estate-wide agent map here.

07 Future edge cases

Short, because we cannot fully stop the model from guessing. We can only keep the fence small and the write path single.

  • New confuse-case = new example SQL + one Don’t line. Do not write a second architecture.
  • One write path. The Genie Text box is the script string. Do not keep a parallel “real” instruction somewhere else.
  • After any edit: new chat + a short confuse-set. Old threads replay old instructions.
  • Cannot fully stop GROUP BY ALL, ILIKE, or thread replay. Design assumes they will happen. Keep the view set small so a guess stays inside the family.
  • No Export-to-metric-view. Genie consumes. It does not author.
  • No second formula. RC-1. If a batch job contains SQL that is not the Metric View compile (except demo 1 / Track A), the architecture has already failed.
