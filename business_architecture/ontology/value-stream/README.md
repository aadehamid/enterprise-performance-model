# value-stream: value streams, stages, capabilities and their processes

The `value-stream` module brings the value-stream overlay into the ontology: the Commercial Hydrocarbon Lifecycle (`../../business_process/value_stream_commercial_lifecycle.json`) and Order to Cash (`../../business_process/value_stream_order_to_cash.json`). Each value stream has stages in sequence; each stage has value-stream processes; each value-stream process uses one capability, and may realize process-map processes by IRI (57 of the 58 did; all 58 since 2026-10-23, EPM-DEC-001-0090), produce or consume data products (20 of the 58 do), and carry cited measure links. The overlay references process nodes and never duplicates them (playbook, Step 7). It holds definitions only (EPM-DEC-001-0005). Its namespace is `https://w3id.org/lsc/ontology/modules/value-stream/`; its build reads `core` 2.3.0 (2.2.0 until 2026-10-23, EPM-DEC-001-0089; 2.1.0 until 2026-10-22, EPM-DEC-001-0076), and it depends on the `data-product` module and the `kpi` module; its released 1.0.0 package requires `core` 2.2.0, 1.1.0 requires `core` 2.3.0 (EPM-DEC-001-0090), and 1.2.0 requires the current `core`, `data-product` and `kpi` releases (EPM-DEC-001-0106). EPM-DEC-001-0054 records the design.

| File | What |
|---|---|
| `vocabulary.ttl` | Classes (value stream, stage, capability, value-stream process, measure link), properties, and the measure-relationship code list (the schema's `informs`, `benchmarks`, `measures-performance`) |
| `shapes.ttl` | SHACL shapes, with a stated cardinality on every property: a stage in one value stream, a value-stream process in one stage with one capability, at most four data products per relation, a measure link naming one kpi measure with its basis and no measure kind |
| `build_value_streams.py`, `value-streams.ttl` | The build: 2 value streams, 12 stages, 21 capabilities, 58 value-stream processes, 73 links to core processes (72 before MPC-P10.2, 2026-10-23, EPM-DEC-001-0090), 9 produces and 37 consumes links, 7 measure links and 4 flows. `--verify` fails unless `value-streams.ttl` equals a fresh build. `scripts/check.sh` runs it |
| `test_value_streams.py` | Tests: the vocabulary, the build is current and its figures match a hand count, every link keeps the source's target and relationship, pinned examples, gap notes create nothing, every measure relationship a top concept both ways, no shape message with an apostrophe, no IRI of the 1.1.0 package gone, and SHACL accepts the module and rejects broken items |

Until 2026-10-22 the module was not released; a release needed the decision owner's approval. *2026-10-22:* released as 1.0.0, with the decision owner's approval of the release plan (EPM-DEC-001-0077). The package is in `../releases/value-stream/1.0.0/`. *2026-10-23:* 1.1.0, with the decision owner's approval of the close-out releases, is in `../releases/value-stream/1.1.0/` (EPM-DEC-001-0090). *2026-10-26:* 1.2.0, a minor Claude approved under the delegation, is in `../releases/value-stream/1.2.0/`: the three measure relationships are top concepts both ways (EPM-DEC-001-0106).

Not carried over, by the schema's rule or EPM-DEC-001-0054: the `gapAnalysis` entries (documentation only), a flow's free-text note, each process's slide letter, and the files' domain as a core business-domain code (kept as written in `vs:sourceDomain`).
