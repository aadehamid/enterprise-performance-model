Modules#

The ontology ships as modules, each released and versioned on its own. core is the process map, and most other modules add one kind of thing and link it to core's processes. Three do not: market-data links to kpi's measures, ref-mpc holds company facts in the terms of organization and party, and integration holds rules about the other modules' links. MODULES.md shows each link with an example quoted from the releases.

ModuleWhat it is for
coreThe process map: processes as a hierarchy, the approved relationships between them and their evidence
organizationRoles, RACI assignments, and the control relationship between legal entities
partyThe customer domain: the customer model, customer systems and data flows, and the customer lifecycle
kpiWhat each measure means, never its value, with the population it counts
data-productThe data-product portfolio: segments, product lines and data products
value-streamThe value streams, as an overlay of steps that realize core processes
systemThe systems, office tools and working documents the process map names
laneThe office lanes, and the processes the process map places in them
market-dataThe recipes of market series, such as crack spreads, never their prices
ref-mpcThe company-specific facts: MPC and MPLX; the only module that is not company-neutral
integrationRules across modules: which links certify (placement), which source wins (authority), and what consumers may bind and answer (consumer)

For versions, what each module requires and triple counts, run uv run --with rdflib python scripts/epm_facts.py modules. It also says what each release was built from where its manifest records that ("built from (release manifest)"); for the other releases it shows the source folders the builder packages today ("sources (builder today)"), which a later change to the builder can move away from what the release was built from. For which processes have a RACI assignment, a system, a KPI, a lane, a value-stream step or a data product, run uv run --with rdflib python scripts/epm_facts.py coverage (see --help for other process sets). Standing conventions#

  • Source of truth: ../business_process/downstream_process_map.json. The ontology models those processes; APQC is a consistency reference.
  • URI base: https://w3id.org/lsc/ontology/, a placeholder: not registered with w3id.org and not hosted, because the domain may change (EPM-DEC-001-0039).
  • License: this folder's contents are proprietary, all rights reserved. APQC-sourced material is used under the APQC/IBM license terms — attribution travels with every distribution (see ../reference/README.md).
  • HTML pages: each reading document here (this README, MODULES.md, the module READMEs and the others scripts/build_docs_html.py lists) has an .html page beside it, generated from the Markdown, and the decision records are one page, ../domain/decisions/decisions.html. Edit the Markdown, then run python3 scripts/build_docs_html.py from the repo root; scripts/check.sh fails while a page is stale.
