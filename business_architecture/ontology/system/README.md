# system: the systems the process map names

The `system` module holds the systems, office tools and working documents that the process map's `systems` fields name, and links each one to the processes that use it (competency question 6). Its namespace is `https://w3id.org/lsc/ontology/modules/system/`; its build reads `core` 2.4.0 for process IRIs (since 2026-10-26, EPM-DEC-001-0105; 2.3.0 from 2026-10-23; 2.2.0 until 2026-10-23, EPM-DEC-001-0089; 2.1.0 until 2026-10-22, EPM-DEC-001-0076); its released 1.0.0 package requires `core` 2.2.0. EPM-DEC-001-0055 records the design.

| File | What |
|---|---|
| `register.csv` | Every distinct string in the map's `systems` fields (45; 37 until MPC-P11, EPM-DEC-001-0104), with the systems it names and the rule: `exact`, `spelling` (a merge on spelling only), `split` (a string that names several systems, split on "/"), or `no-system` (Manual, TBD and two plans to build something) |
| `systems.csv` | The 39 systems the process map names (32 until MPC-P11 added seven, EPM-DEC-001-0104), each with its name, alternative labels and kind: application, office tool or working document; `other-systems.csv` adds the two that other sources name, MIPS and Databricks (item F, EPM-DEC-001-0100) |
| `definitions.csv`, `sources.csv` | Items G and F (EPM-DEC-001-0099, 0100) and EPM-DEC-001-0103: the definitions of 39 of the 41 systems (18, then the 14 internal ones drafted from the repository in 1.3.0, then MPC-P11's seven in 1.4.0 with the `party` module's definitions; TopDay and VALT wait for their owners), each in Claude's words from its cited sources, and notes in place of the standard one; the sources' titles and tiers, shared with the `party` module |
| `vocabulary.ttl`, `shapes.ttl` | The class, the `supports` and `systemKind` properties, the system-kind code list, and the SHACL shapes |
| `build_systems.py`, `systems.ttl` | The build: 41 systems (the map's 39, plus MIPS and Databricks) and 306 links to 162 processes. 165 processes have a `systems` field; three of them name only Manual, TBD or a plan. `--verify` fails unless `systems.ttl` equals a fresh build. `scripts/check.sh` runs it |
| `test_systems.py` | Tests: the build is current, the figures, the spelling merge, a split, Manual creating no system, kinds, pinned links, MPC-P11's systems and its 21 links in the map, and SHACL accepting the module and rejecting an invented definition, two kinds, a kind off the list and a missing note |

Until 2026-10-22 the module was not released; a release needed the decision owner's approval. *2026-10-22:* released as 1.0.0, with the decision owner's approval of the release plan (EPM-DEC-001-0077). The package is in `../releases/system/1.0.0/`. *2026-10-25:* `system` 1.1.0, with the definitions below, released through the item G pull request (#379; EPM-DEC-001-0099). *2026-10-25 (later):* released as 1.2.0 (`../releases/system/1.2.0/`): `other-systems.csv` adds MIPS and Databricks, which the process map does not name, each marked `sys:namedBy` its source, and MPR gains a definition (EPM-DEC-001-0100). *2026-10-26:* released as 1.3.0, with the internal systems' descriptions drafted from the repository, approved by Claude under the delegation (EPM-DEC-001-0103). *2026-10-26 (later):* released as 1.4.0, with MPC-P11, which the decision owner accepted: 12 customer-lifecycle processes name the systems they use, 21 links, and seven systems join the module; Claude approved the minor release under the delegation (EPM-DEC-001-0104).

39 of the 41 systems have a definition (EPM-DEC-001-0103, 0104). TopDay and VALT are MPC-built, and no source in the repository says what they do, so each carries a note that its description waits for its owners (EPM-DEC-001-0099; `../business-closeout.md`, point 12). Until 2026-10-25 no source in the repository said what each system does, so no system had a definition, and each carried that note. These are internal system names, which EPM-DEC-001-0040 item 3 allows in this repository. *2026-10-25:* 15 systems gain a definition, from their vendors' own descriptions (marked as such) or the decision owner's, and five take their full name as the preferred label, with the abbreviation as an alternative; the other 17 keep the note (item G, EPM-DEC-001-0099); they shipped in `system` 1.1.0. *2026-10-26:* MPR gains a definition in 1.2.0, so 16 of the map's 32 keep the note (EPM-DEC-001-0100). *2026-10-26:* `system` 1.3.0 defines 14 more from the repository, so only TopDay and VALT keep the note: 32 of the 34 systems are defined (EPM-DEC-001-0103). *2026-10-26 (later):* the seven systems MPC-P11 adds take the `party` module's definitions, so 39 of the 41 are defined (EPM-DEC-001-0104).
