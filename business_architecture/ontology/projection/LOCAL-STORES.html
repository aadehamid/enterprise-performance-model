The standard is one local Neo4j and one standing Jena, with AuraDB a copy of the local Neo4j and epm_triples holding the same releases as a Delta table. README.md, "What each store holds", gives the policy for each module's three graphs. One driver run loads all of them. 2026-11-01: the container epm-lpg and its login leave at the next reload, which removes them; the paragraphs below dated before that day describe what the stores held then.

Since 2026-10-26 the stores below stay loaded after a run, so the decision owner can explore the graph, the ontology and the Databricks data, as they asked that day (../step4/review-evidence/decision-owner-answers/answers-2026-10-26-keep-stores.md). Before that date each run removed its local containers. This page says where each store is, which command refreshes it and where its login lives. No password is written here: each one stays in its env file. The run.env files are written by the scripts with mode 600; the Aura and Databricks env files are yours, so set their mode yourself (chmod 600). 2026-10-27: the four ontology stores (both local Neo4j, AuraDB and epm_triples) are empty. 2026-10-28: the four ontology stores (both local Neo4j stores, AuraDB and epm_triples), empty since the purge of 2026-10-27, were reloaded from that day's releases, with kpi 1.3.0. ontology-stores-runbook.html gives each store's figures.

2026-10-29: both local Neo4j stores and AuraDB also hold the pricing demo's technical graph and decision trail (E5): 134 nodes labelled Tech (2026-10-29, later: 142 since E6 added the outside-context tables), never Resource, with edges only from them, so the projection's counts and hash, which read :Resource nodes and the edges between them, do not change. A pipeline reload, a driver run or a purge removes them; load them again with uv run --group graph python -m pricing_demo.tech_graph load from the demo's folder.

2026-10-29, later: each of the four ontology stores holds a marker of the release set it was loaded from: a node labelled EpmStoreMarker (never Resource) in each Neo4j store, a row in epm_store_markers beside epm_triples. sync_stores.py check reports which stores are behind main's newest catalog, and sync_stores.py sync reloads them (AuraDB and Databricks only with --cloud). A pipeline reload, a driver run or a purge removes a Neo4j store's marker; mark it again with sync_stores.py mark. The runbook's "Keeping the stores in step" gives the commands and the release-tag workflow's secrets.

2026-11-02: each store that holds the technical graph also holds its marker, a digest of the graph files it was loaded from: a TechGraphMarker node in each Neo4j store and the named graph urn:pricing-demo:graph:tech-marker in Jena, which tech_graph load writes, and the row tech_graph in epm_store_markers for the Delta copy, which tech_graph sync writes. sync_stores.py check reports it on a tech:<store> line, with the content the store holds compared with the files, and a release is done only when every line reads current.

2026-11-02: stores loaded from releases that hold the logical-model module, as a share release's do, also hold its logical models (EPM-DEC-001-0113, amendment "the stores"): each model's ER Studio export and annotation layer as named graphs in Jena and epm_triples, and each model as a subgraph labelled LogicalModel, never Resource, with a LogicalModelMarker, in each Neo4j store. logical_models.py load loads them, and sync_stores.py check reports the subgraph on an lm:<store> line. main holds no logical-model package, so the stores on this page hold none of it, and check prints no lm: line.
