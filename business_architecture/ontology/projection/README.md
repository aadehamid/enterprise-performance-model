# Property-graph projection (Step 12)

Projects the ontology into a Neo4j labelled property graph with the `ontology-to-lpg` skill's driver, `run_projection.py` (method version 2.3; Rule 4a, qualified-relation nodes). Turtle stays the master copy; the graph can be rebuilt from it at any time. The design is EPM-DEC-001-0036, and the policy and the one local Neo4j are EPM-DEC-001-0111. It projects every released package under `../releases/`, each at its newest version, with each package's own shapes.

## What each store holds

Each module package has three graphs: `<module>.ttl` (the content), `shapes.ttl` (the rules) and `catalog.ttl` (the DCAT release record). `../MODULES.md` describes each module's three files and what each package is built from.

| Store | `<module>.ttl` | `shapes.ttl` | `catalog.ttl` |
|---|---|---|---|
| Jena, one local standing Fuseki, which also holds the technical graph as two named graphs of its own | All | All | All |
| Databricks, the Delta table `epm_triples` | All | All | All |
| Neo4j, one local store and its copy in AuraDB | All | Not as nodes: they validate the release | Not in full: one `ModuleRelease` node per module |

- **All the content.** Neo4j gets all of `<module>.ttl`, with no selective projection, so the round trip keeps proving 0 lost and 0 added.
- **The shapes validate the release.** pySHACL runs them before the load and n10s runs them in the graph at the load. They are not projected as nodes.
- **One release record per module.** A node labelled `ModuleRelease`, linked to the module's `owl__Ontology` node by `DESCRIBES`. Its fields are `module`, `version`, `version_iri`, `ontology`, `download_url`, `conforms`, `in_graph_constraints`, `violations`, `shapes_sha256`, `projection_version` and `loaded_at`, each from the release's own files or the run's report. `conforms`, `in_graph_constraints` and `violations` describe the whole load, because the shapes run over every module together. The node has no `Resource` label and the link starts outside `Resource`, so the graph hash, the counts, the module tags and the round trip read neither, and no field enters a hash. To read them: `MATCH (r:ModuleRelease)-[:DESCRIBES]->(o) RETURN r.module, r.version, r.conforms, r.violations, r.loaded_at, o.uri ORDER BY r.module`.
- **One form, one local store.** There is one local Neo4j and one standing Jena, and AuraDB copies the local Neo4j. Every node and relationship carries a `graph` property giving its release's version IRI, and the ontology import adds `n4sch__` schema nodes and relationships.
- **Two labels on a class.** A class is one node with two labels: `owl__Class`, from its own triple in the Turtle, and `n4sch__Class`, from the ontology import, which also writes the schema relationships. They are not two nodes. Count classes with one label: 46 nodes carry both.

## Run the projection

`rebuild_stores.py` does all of this, and the stores' other steps, from one environment file. By hand: run it after any input or shape changes. You need Docker, [uv](https://docs.astral.sh/uv/) and Java 11 or later ([ROBOT's Getting Started](https://robot.obolibrary.org/): "make sure you have Java 11 or later installed"). The driver is in the `ontology-to-lpg` skill, in the `scripts/` folder of `$SKILLS/ontology-to-lpg`.

1. Download ROBOT 1.9.10 (it runs the ELK reasoner), and check its SHA-256. If the checksum differs, stop: the driver refuses another file. The driver fetches and checks the n10s (neosemantics) plugin itself.

   ```bash
   mkdir -p ~/epm-lpg; ROBOT=~/epm-lpg/robot.jar
   curl -L -o "$ROBOT" https://github.com/ontodev/robot/releases/download/v1.9.10/robot.jar
   shasum -a 256 "$ROBOT"
   # expect 16a73c074f3df359a7338a84b4e0788785fe06117f931bb9796e9619ea776105
   ```

2. Run the driver. It checks, reasons, loads the local Neo4j, writes the release records, copies to AuraDB, round-trips Jena and Databricks, and rebuilds from Databricks. `--skip copy,databricks,rebuild` leaves the cloud stores alone. It generates the local Neo4j's password and keeps it in its output folder.

   ```bash
   cd "$SKILLS/ontology-to-lpg/scripts"
   uv run --no-project --with rdflib python3 run_projection.py --config "$EPM/business_architecture/ontology/projection/skill-run/epm-run.json"
   ```

3. Take the result into this folder, from this folder. It refuses a run that read other inputs than this tree's, or whose report did not pass. Commit `inferred.nt`, the manifest and the report together.

   ```bash
   uv run --with rdflib --with pyshacl python pipeline.py record --run ~/lpg-out/epm
   ```
