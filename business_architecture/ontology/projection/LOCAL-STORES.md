# The stores kept for exploration

Since 2026-10-26 the stores below stay loaded after a run, so the decision owner can explore the graph, the ontology and the Databricks data, as they asked that day (`../step4/review-evidence/decision-owner-answers/answers-2026-10-26-keep-stores.md`). Before that date each run removed its local containers. This page says where each store is, which command refreshes it and where its login lives. No password is written here: each one stays in its env file. The `run.env` files are written by the scripts with mode 600; the Aura and Databricks env files are yours, so set their mode yourself (`chmod 600`). *2026-10-27:* the four ontology stores (both local Neo4j, AuraDB and `epm_triples`) are empty. With the decision owner's approval, "Yes, purge those four (Recommended)", they were purged that day, and the decision owner chose "Wait, reload at Part 2 (Recommended)": the stores stay empty, and the reload is the first step of Part 2, after the close-out answers ship, with the counts and hash checks (`../step4/review-evidence/decision-owner-answers/answers-2026-10-27-stores.md`). The pricing demo's Postgres and `idp_sbx` stay loaded.

*2026-10-28:* the four ontology stores (both local Neo4j stores, AuraDB and `epm_triples`), empty since the purge of 2026-10-27, were reloaded from that day's releases, with `kpi` 1.3.0. `ontology-stores-runbook.html` gives each store's figures.

*2026-10-29:* both local Neo4j stores and AuraDB also hold the pricing demo's technical graph and decision trail (E5): 134 nodes labelled `Tech`, never `Resource`, with edges only from them, so the projection's counts and hash, which read `:Resource` nodes and the edges between them, do not change. A pipeline reload, a driver run or a purge removes them; load them again with `uv run --group graph python -m pricing_demo.tech_graph load` from the demo's folder.

The Postgres data sits in the named Docker volume `pricing-demo-pgdata`, so a reboot keeps it. The container has `restart: unless-stopped`; after a reboot, start all three local containers as `ontology-stores-runbook.html` says, whichever came back by itself. `replace_target` is on in `skill-run/epm-run.json`, so each driver run replaces what Aura holds.

`ontology-stores-runbook.html`, beside this page, explains the end-to-end workflow with diagrams, and gives the commands to check, stop, start, restart after a reboot, purge and reload each store. Open it in a browser.

The scripts that build and check these stores are in the repository: `pipeline.py`, `run_local.sh` and `skill-run/` here, and `pricing_demo/` and `tests/` in the demo.
