Secure Proxy Architecture & Guardrails

To support strict corporate compliance and data governance, the platform implements a zero-trust model for database interactions. All database credentials and parameters (such as URIs, usernames, and passwords) are maintained in environment variables loaded securely inside the FastAPI backend.

Zero Client-Side Credentials

No browser context or client-side files import direct driver scripts or pass credential tokens. Direct database writes, edits, and reads in the browser are completely abolished.

Secure Endpoints

Interactive queries, 1-hop expansions, and analytical feedbacks are proxied strictly through designated REST endpoints (/ask, /api/expand, and /api/feedback) running backend validations.

Strict Read-Only Guardrails

Before any Cypher query generated by the AI is run against the database, the backend compiles and intercepts it via regex. If any destructive command (CREATE, `MERGE`, `DELETE`, `SET`, `REMOVE`, `DROP`) is detected, the transaction is rejected immediately to protect graph integrity.

Recursive NaN Sanitizer (Crash Protection)

Standard JSON serializers will fail and crash the server when trying to serialize standard Python float NaN or `Infinity` values. The backend incorporates a recursive clean_nans utility that intercepts, cleanses, and converts any dirty database floats to JSON-compliant null elements before returning payloads.

Self-Healing & Auto-Correction Pipeline

Natural Language-to-Cypher engines are naturally prone to logical, schema-guessing, and spelling anomalies. To achieve high production-grade accuracy, we have integrated a self-healing trial-run loop with automated corrections.

1. Complexity Classifier

Before running the self-healing process, the query is analyzed. Standard simple lookup queries execute instantly, while complex queries containing deep joins (*1..5), legacy schemas (:Legacy), or master data mappings invoke the full auto-healing loop.

2. Pre-Flight `EXPLAIN` Validation

FastAPI validates queries by running rapid 1-millisecond EXPLAIN compiler pre-flights directly in the Neo4j database engine. This validates syntax, schema patterns, and conformed property spellings before data is actually loaded.

3. 2-Retry Self-Healing Loop

If the compiler pre-flight fails, or if it succeeds but retrieves 0 records (indicating a wrong schema name or join assumption), the error message is packed and fed back to the LLM to dynamically self-heal the Cypher query up to 2 times.

Hybrid Session Persistence & Cold Archival

Conversational logs and user feedbacks are persisted using an elegant, hybrid storage model combining Neo4j Graph Database (for structural lineage telemetry) and a local SQLite Archive (for high-volume long-term cold storage).

Active Chat & Chaining (Neo4j)

Active conversation turns (under 30 days old) reside entirely in Neo4j. Messages are chained via [:NEXT] edges into a chronological linked list, with an active [:LAST_MESSAGE] pointer for fast updates.

Automated 30-Day SQLite Archival

To prevent graph bloat and maintain peak cache performance, a transaction-triggered worker automatically archives messages older than 30 days into a local SQLite database (chat_history.db) and deletes them from Neo4j.

Permanent Lineage Telemetry Guard

Messages that receive "poor" feedback ratings are permanently exempted from SQLite archival. They remain in the Neo4j active graph forever, enabling persistent lineage-failure graph analytics.

Parallel Search & Merge Pattern

When users query conversation logs or feedback, the backend concurrently queries Neo4j (Cypher) and SQLite (SQL) in parallel, deduplicates records, sorts them chronologically, and returns a single unified conformed grid.

Canonical Schema & Medallion Rules

All generated Cypher queries must strictly adhere to the following naming conventions and database schemas to ensure exact matching and zero cartesian explosions:

Schema Prefix Medallion Layer Labels & Description
udm_core.*, mdm_core.* Silver Conformed Dimensions and Facts. Target of REFACTORED_TO.
replica* Replica 1:1 copies of operational source tables.
sem_.* Semantic Views consumed directly by reports. Must have at least 1 DERIVED_FROM.
_core.* Gold Business-specific core aggregates.
dwh*, persistence.*, staging.* Silver / Legacy Pre-standard legacy schemas. Must carry the :Legacy label.

Critical Cypher Traversal Guidelines:

  • Relationship Aliasing: Every relationship traversal must carry an explicit alias (e.g. -[r1:DERIVED_FROM]->) to ensure NVL renders edge details in the browser canvas.
  • Optional Match Enforcement: Always use OPTIONAL MATCH for all traversals beyond the initial anchor node to prevent silent row filtering.
  • Variable Length Lineage: Utilize DERIVED_FROM*1..5 for lineage searches since path depths vary dynamically across conformed layers.

Running the Platform Locally

To run the Lagos Refining & Supply Company Semantic Portal (both the FastAPI backend gateway and the Vite React frontend) locally, execute the following commands in separate terminal windows:

1. Launch Backend Gateway (FastAPI)

# 1. Activate the Python virtual environment at the root directory
source .venv/bin/activate             # macOS/Linux
.venv\Scripts\Activate.ps1           # Windows PowerShell

# 2. Navigate to the backend directory
cd neo4j_text2cypher_fullstack/backend

# 3. Start the FastAPI backend server
python -m app.main

The gateway starts and runs on port 8000.

2. Launch Frontend UI (Vite React)

# Navigate to the frontend directory
cd neo4j_text2cypher_fullstack/frontend

# Install dependencies on first run
npm install

# Start the development server
npm run dev

The portal opens in your browser at http://localhost:5173/.
