This is the Domain Modeling lane only. The ontologist authors Turtle modules and the design standard; the KPI Store Engineer authors the Store catalog and certified formulas. Nothing here invents a workshop, a gate, or a CW number. Where the planning docs name a form, that form is quoted. Where they say “document” or “register” without naming Word vs HTML vs git, that gap is marked and a working recommendation is given. Slides are never the source of truth unless a cited row says so.

Locks — compact, once · do not reopen in this briefing
  • Customer = order-to-cash. Preferred terms: Customer Account + Sold-To / Bill-To / Payer. Ship-To = location, not a role. CreditAccount sits on the payer. Loading-Authorized Party ≠ the Authorization object. Do not overload “Customer.”
  • Ops / Tech = plan-to-produce constraints. “Produce” includes buy, exchange, throughput, and terminal blend. TechnologyConstraint is first-class if Technology is in (DP-17 / CW1) — not a property of Operational.
  • D-M18: LimitValue is n-ary (value, unit, quantity kind, direction, reference conditions, valid-time). Constraint ≠ Threshold ≠ Breach ≠ Binding. Store KPIs reference constraints; they do not subclass them.
  • C-10: ontology = meaning SoT. Store + consumption SL = certified formula SoT. Domain Modeling authors the ubiquitous language and the domain model, not certified formulas. Silver is a one-way projection (Q-08 / CK-03).
  • C-11: never write “semantic layer” unqualified. Say ontology layer or consumption semantic layer.
  • CV / CQ is a real gate (G3 / G4). CW7 previews the CQ method only. CW11 = Customer UL freeze. CW18 = Constraints CV → CQs → then is-a. DDO signs the CV.
  • D-M19: four-question test first. Harvest = sense-inventory of agreed meaning, not a label-copy of “Customer.” Inheritance confers no approval status.
  • Pipeline (meaning side, production language, order is load-bearing): Controlled vocabulary → metadata standards → taxonomy → thesaurus (SKOS) → ontology → knowledge graph. Domain Modeling owns the left of that chain through the domain model. Do not skip to graph-first.
  • DP-18 Hamid slice gate: conceptual / domain build (CW11+ / Turtle) waits on the slice. Workshops through CW2 and the P1 assessment stay fine.
  • G2 = no running triple store required. G5 = 1–2 Store pilots (Store lane; a seam only).
  • Databricks = programme consumption-SL platform + compiler. Unbilled demo stays MetricFlow. Domain Modeling does not author that compile.
  • Constraints ownership is federated (coordinating owner + family stewards). ER/Studio is harvest input, not meaning SoT. Process linkage is not definitional lineage.
